## 2. 全仓统一命名与数据角色

| 名称 | 代表什么 | 不代表什么 |
|---|---|---|
| M01–M07 | 机动类型，完整映射以第 3 章为准 | 不是训练/验证/测试集 |
| 采集 `run_id` / `group_id` | 实际机动记录及航次/会话分组；原始 `voyage_id` 经明确映射导入 | 不是按采样窗口任意重分的数据组；不与训练实验 `run_id` 混用 |
| `model_train / model_val / model_test` | 模型拟合、开发选型、最终留出用途 | 不因同属一类机动而合并 |
| `ood_calibration` | 独立确定 OOD 检测配置和阈值 | 不作模型最终精度或安全性证明 |
| `policy_train / policy_dev / policy_test` | 策略训练、开发调参、冻结候选测试场景 | 不与实船模型数据角色互相替代 |
| M-EMP / M-ID / M-HYB | 第 6 章的经验、同船辨识、灰箱模型 ID | 不是机动 M01，也不是控制器 |
| C-BASE / C-PPO / C-RES | 第 6 章控制器 ID | 不与第 4 章 C1–C4 模型闭环判据混用 |
| S1–S4 / H1–H4 | 船舶任务 / 人形任务 | H1 任务 ID 不表示某一机器人型号 |
| P0–P6 / G0–G6 | 实施阶段 / 绑定版本与任务的阶段出口 | 日历周到期不等于出口通过 |

第 3 章采集 `role=train/val/test` 导入后分别对应 `model_train/model_val/model_test`，OOD 用 `role=calibration` 对应 `ood_calibration`；其他用途另命名。第 5 章 L1–L4 只表示可行性层级，跨章引用必须带“第 5 章评估层级”前缀，不能写成机动或数据用途。

## 3. 实施前仍需填写的项目

| 项目 | 必填信息 | 缺失时的处理 |
|---|---|---|

| 人形平台 | 模型/许可证、关节顺序、动作/PD/电机、时序、接触和保护协议 | 先复现仿真参考任务，不直接套用船舶配置 |
