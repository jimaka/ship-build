## 为什么学这一章

前面九章我们有了仿真环境（第 4、8 章）、辨识出的模型参数（第 7 章），研究项目的下一步就是让计算机自己学会操纵这艘船——这正是研究文档 `research/05-RL取代传统控制律可行性评估.md` 和 `research/06-船舶RL到人形机器人控制实施计划.md` 的主题。强化学习（Reinforcement Learning, RL）是一种"试错学习"：不给标准答案，只给一个打分规则，让程序自己摸索怎么拿高分。它的概念并不多，但工程上的失败大多不出在算法本身，而出在三件事上：环境接口没约定清楚、奖励写歪了、评估自己骗自己。研究文档 §4.5（`research/04-验证协议与RL契约.md`）和 §6.5（`research/06-船舶RL到人形机器人控制实施计划.md`）用大量篇幅给这三件事立规矩。本章用一个能几分钟跑完的最小例子，把这些规矩亲手各踩一遍、各验证一次，第 11 章再把它们组装进完整流水线。

## 10.1 RL 五要素：从第 8 章的 Env 到强化学习环境

第 8 章我们写过仿真环境类：`reset()` 回到初始状态，`step(action)` 推进一步。强化学习只需要在这个骨架上补两个东西：**奖励**和**回合结束信号**。先统一一下术语（首次出现的领域词用一句话解释）：

| RL 要素 | 通俗解释 | 本章保向任务里是什么 | 在接口里的位置 |
|---|---|---|---|
| 状态/观测 obs | 智能体每一步能看到的数字 | `[航向误差, 转艏角速度]` | `reset()` / `step()` 的返回值 |
| 动作 action | 每一步能拧的"旋钮" | 归一化转艏力矩 `a∈[-1,1]`（教学简化：把双推进器能产生的转艏效果合并成一个标量） | `step(action)` 的入参 |
| 奖励 reward | 每一步的得分，可正可负 | `-|航向误差| - 0.1·a²`，失败再扣 50 | `step()` 的返回值 |
| 回合 episode | 一"局"：从开局到结束 | 最多 200 步（20 秒），偏出 ±90° 判失败 | `reset()` 开局；`terminated`/`truncated` 结束 |
| 策略 policy | 从状态查动作的函数，学习的目标就是它 | 线性策略 `a = clip(w·[err, r, 1])` | 写在环境外面的代码 |

几个名词解释：**艏向角** `psi` 是船头指向的角度；**保向**指保持船头对准目标方向；**转艏角速度** `r` 是船头转动的快慢；一回合奖励的累加值叫**总回报**（return），是衡量策略好坏的总分。

"保向"是船舶控制里最基础的任务，真实项目中它对应研究文档 §6.3.2 的船舶起步接口——区别只是真实接口的动作是四维推进器目标 `(alpha1_cmd, rpm1_cmd, alpha2_cmd, rpm2_cmd)`、观测字段更多，本章把它压缩成一个标量动作和两个状态，这是教学简化。

还有一个接口细节值得现在就立好规矩：`step()` 返回两个结束标志——`terminated`（任务意义上的结束，如失败、到达目标）和 `truncated`（外部时间上限到了）。研究文档 §4.5.4 明确规定环境采用这种五元组契约、废止只有一个 `done` 的旧写法，§6.5.3 强调两者不能混用：失败是"这局你输了"，截断只是"计时器响了"，在真正的价值学习算法里两者的后续处理不同（本章的算法不涉及，但接口要先对）。

```python
import numpy as np


def wrap_angle(angle):
    """把角度包络到 (-pi, pi]，防止 179° 与 -179° 之间跳变。"""
    return (angle + np.pi) % (2 * np.pi) - np.pi


class HeadingEnv:
    """教学简化的船舶保向环境（在第 8 章 Env 基础上加上奖励与回合）。"""

    def __init__(self, dt=0.1, max_steps=200, lam=0.1, seed=0):
        self.dt = dt
        self.max_steps = max_steps
        self.lam = lam      # 控制量惩罚权重
        self.n_max = 1.0    # 归一化最大转艏力矩（教学简化）
        self.damp = 0.5     # 转艏阻尼（教学简化：阻尼越大船头越"钝"）
        self.rng = np.random.default_rng(seed)
        self.psi_ref = 0.0  # 目标艏向角

    def _obs(self):
        err = wrap_angle(self.psi - self.psi_ref)
        return np.array([err, self.r])

    def reset(self, psi0=None):
        if psi0 is None:
            psi0 = self.rng.uniform(-np.pi / 3, np.pi / 3)  # ±60° 内随机
        self.psi, self.r, self.t = psi0, 0.0, 0
        return self._obs()

    def step(self, action):
        a = float(np.clip(action, -1.0, 1.0))   # 硬限幅
        # 教学简化的一阶转艏动力学：力矩推动角加速度，阻尼消耗它
        r_dot = a * self.n_max - self.damp * self.r
        self.r += r_dot * self.dt
        self.psi += self.r * self.dt
        self.t += 1
        obs = self._obs()
        reward = -abs(obs[0]) - self.lam * a * a
        terminated = abs(obs[0]) > np.pi / 2   # 偏出允许域 → 任务失败终止
        truncated = self.t >= self.max_steps   # 时间上限 → 截断
        if terminated:
            reward -= 50.0  # 失败惩罚，防止"早点失败反而少扣分"
        return obs, reward, terminated, truncated, {"clipped": a != action}
```

环境里的两处设计直接对应研究文档的契约：动作被 `clip` 到 [-1, 1] 并在 `info["clipped"]` 里留痕——§4.5.1 要求硬限幅必须可见、不允许静默裁剪；`terminated` 对应 §4.5.4 的"离开允许域定义为任务失败"。先用一个乱动的随机策略试跑一回合：

```python
env = HeadingEnv(seed=0)
rng = np.random.default_rng(0)
obs = env.reset()
total = 0.0
while True:
    action = rng.uniform(-1, 1)      # 随机策略：完全不看观测，瞎拧
    obs, reward, terminated, truncated, info = env.step(action)
    total += reward
    if terminated or truncated:
        break
print("随机策略回合总回报:", round(total, 1), "| 结束原因:",
      "terminated" if terminated else "truncated")
```

预期输出：

```text
随机策略回合总回报: -117.0 | 结束原因: terminated
```

随机左满舵右满舵的结果是把船头甩偏超过 90°，回合以失败告终，还吃了 -50 的失败惩罚。这个负分就是我们的起点——接下来看看能不能学出一个大幅超过它的策略。

## 10.2 奖励 shaping：奖励就是你对"好行为"的书面定义

奖励函数的设计行话叫 **reward shaping**。我们的保向奖励是：

```text
r = -|航向误差| - 0.1 × 动作²   （失败终止额外 -50）
```

逐项解释为什么这样设计：

- **`-|航向误差|`（主项）**：误差越大扣分越多，每一步都在扣。用绝对值而不用平方，是为了小误差时仍有持续的改进压力（平方在误差 0.01 时只扣 0.0001，约等于不扣）。误差用弧度，和状态量纲一致。
- **`-0.1 × 动作²`（控制量惩罚）**：推进器动作是要耗能、会磨损的，不罚的话最优解是"往死里打满舵"。系数 0.1 是权衡：太大→策略不敢动作、精度变差；太小→动作粗暴。这类系数要靠实验调，调的时候只看开发场景（见 10.4 的纪律）。
- **失败 -50（终局惩罚）**：我们的奖励每步都是负数，如果不给失败额外惩罚，"赶紧偏出 90° 结束回合"反而少扣分——智能体会学会自杀。10.5 节会亲眼看到这个现象。

先把一项一项打印出来，建立直觉：

```python
obs = env.reset(psi0=np.radians(30))
print("步 | 航向误差(°) | 动作 | -|误差| | -0.1*a^2 | 合计")
a = 0.5
for k in range(3):
    obs, reward, terminated, truncated, _ = env.step(a)
    print(k, "|", round(np.degrees(obs[0]), 1), "|", a, "|",
          round(-abs(obs[0]), 3), "|", round(-0.1 * a * a, 3), "|",
          round(reward, 3))
```

预期输出：

```text
步 | 航向误差(°) | 动作 | -|误差| | -0.1*a^2 | 合计
0 | 30.3 | 0.5 | -0.529 | -0.025 | -0.554
1 | 30.8 | 0.5 | -0.538 | -0.025 | -0.563
2 | 31.7 | 0.5 | -0.553 | -0.025 | -0.578
```

固定动作 +0.5 反而把误差推得更大，每步扣约 0.55 分——其中误差项占 96%，控制惩罚只占零头。注意一个反常之处：误差在涨，说明这个固定动作是错的；好策略应该根据误差**方向**决定动作方向，这正是下一节要学的东西。

坏奖励的常见样子和后果，先留个印象（10.5 节验证其中一条）：

| 坏奖励设计 | 智能体会学到的行为 |
|---|---|
| 只在误差 < 2° 时 +1，其余为 0（稀疏奖励） | 前期全是一群 0 分，算法分不清哪个瞎猜更好，学得极慢或学不动 |
| 不罚控制量 | 动作长期打满 ±1，能耗和抖动都难看 |
| 每步给固定"时间惩罚"却不给失败惩罚 | 尽快失败结束回合反而赚分——自杀式策略（10.5 节实测） |
| 奖励里混入量纲没对齐的项（角度° 和弧度混用） | 某一项意外主导，行为随单位换算"漂移" |

## 10.3 一个能手写的学习算法：CEM 训练线性策略

学习的对象是一个**策略**。我们选最简单的参数化形式——线性策略：

```text
a = clip(w0·err + w1·r + w2, -1, 1)
```

它其实就是一个可学习的 PD 控制器（第 4 章提过比例-微分控制：`w0` 管"误差多大就回多大力"，`w1` 管"转多快就刹多狠"），只是参数不由人调，而由算法搜。学习算法用 **CEM（Cross-Entropy Method，交叉熵方法）**，思路朴素得像生物进化：

1. 用一个高斯分布（均值 `mean`、标准差 `std`）当"当前猜测"，采样 40 个候选参数 `w`；
2. 每个候选在几个固定初始艏向上各跑一回合，算平均总回报；
3. 留下得分最高的 8 个"精英"，把分布的均值和标准差更新到精英身上；回到第 1 步。

不需要梯度、不需要神经网络，30 行就能写全，对低维参数非常可靠：

```python
def linear_policy(w, obs):
    """线性策略：a = w0*err + w1*r + w2，限幅到 [-1, 1]。"""
    return float(np.clip(w @ np.array([obs[0], obs[1], 1.0]), -1.0, 1.0))


def run_episode(env, w, psi0):
    obs = env.reset(psi0=psi0)
    total = 0.0
    while True:
        obs, reward, terminated, truncated, _ = env.step(linear_policy(w, obs))
        total += reward
        if terminated or truncated:
            return total


def evaluate(env, w, psi0_list):
    return float(np.mean([run_episode(env, w, p) for p in psi0_list]))


def cem_train(env, psi0_list, n_iter=30, n_sample=40, n_elite=8, seed=42):
    """交叉熵方法：高斯采样策略参数 → 留精英 → 更新分布。"""
    rng = np.random.default_rng(seed)
    mean, std = np.zeros(3), np.ones(3)   # 初始猜测：完全不会
    history = []
    for it in range(n_iter):
        W = rng.normal(mean, std, size=(n_sample, 3))
        scores = np.array([evaluate(env, w, psi0_list) for w in W])
        elite = W[np.argsort(scores)[-n_elite:]]
        mean, std = elite.mean(axis=0), elite.std(axis=0) + 1e-3
        history.append(float(scores.max()))
    return mean, history


train_psi0 = np.radians([-60, -30, 0, 30, 60])  # 训练场景：5 个初始艏向
env = HeadingEnv(seed=0)
print("学习前总回报:", round(evaluate(env, np.zeros(3), train_psi0), 1))
w_learned, history = cem_train(env, train_psi0)
print("学到的参数 w =", np.round(w_learned, 3))
print("学习后总回报:", round(evaluate(env, w_learned, train_psi0), 1))
```

预期输出：

```text
学习前总回报: -125.7
学到的参数 w = [-2.704 -1.48   0.   ]
学习后总回报: -7.2
```

解读：`w0=-2.704`、`w1=-1.48` 都是负的——误差为正就施加负力矩、转速为正就施加刹车力矩，方向和人的直觉一致；`w2≈0`，没有多余偏置。总回报从 -125.7 升到 -7.2。画出学习曲线和学习前后的艏向响应（第 5 章的技能；若你的机器上中文标签显示为方框，按第 5 章的方法配置中文字体，或先把标签换成英文）：

## 10.4 评估纪律：先冻结，再打分

策略看起来不错，但"不错"是谁说了算？研究文档 §6.5.1 的规矩是：**先把评估场景表和成功定义写下来冻结，再允许看结果**。场景表至少包含初始状态、目标指令、扰动、时长；成功定义要写明容差和保持时间——这些参数若等看到结果再挑，等于裁判赛后改规则。§6.5.4 进一步要求训练场景（`policy_train`）与最终测试场景（`policy_test`）分别冻结，§4.5.6 提醒保存随机种子有助于复现。我们的迷你版：

- 训练场景：±60° 内 5 个初始艏向（上节已用）；
- **评估场景：另外 5 个训练时没用过的初始艏向，冻结为 `eval_psi0`**；
- **成功定义（先于看结果写下）：全程未失败终止，且最后 20 步 `|航向误差|` 始终 < 2°**；
- 所有随机源带种子（`HeadingEnv(seed=0)`、`cem_train(seed=42)`）。

```python
# 评估规则先于看结果冻结：5 个训练没用过的初始艏向；
# 成功 = 全程未失败终止，且最后 20 步 |航向误差| 始终 < 2°
eval_psi0 = np.radians([-50, -20, 15, 40, 55])
tol = np.radians(2)

success = 0
for p in eval_psi0:
    obs = env.reset(psi0=p)
    errs = []
    alive = True
    while True:
        obs, _, terminated, truncated, _ = env.step(linear_policy(w_learned, obs))
        errs.append(abs(obs[0]))
        if terminated:
            alive = False
            break
        if truncated:
            break
    if alive and max(errs[-20:]) < tol:
        success += 1
print("冻结评估成功率:", success, "/", len(eval_psi0))
```

预期输出：`冻结评估成功率: 5 / 5`。

两点说明：其一，训练与评估用了**同一个动力学环境**的不同初始条件，这是本章的教学简化；真实项目里"评估环境"还包括不同的扰动、参数摄动甚至第二个仿真器（§6.5.4）。其二，5 个场景、1 个种子的结论非常脆弱，§6.5.2 的开发期建议是每任务 5 个训练种子 × 同一套 100 个评估场景、分别报告种子间散布——本章练习 3 会让你先体会多种子的差异。

## 10.5 坏奖励实战：智能体学会了"自杀"

10.2 节表格里"时间惩罚却不给失败惩罚 → 自杀"的预言，现在用 10 行代码验证。有人想催策略快点回正，给每步额外扣 1 分"时间成本"，却忘了保留失败惩罚：

```python
class BadRewardEnv(HeadingEnv):
    """错误示范：每步额外 -1 催它快点，失败终止却没有任何惩罚。"""

    def step(self, action):
        obs, _, terminated, truncated, info = super().step(action)
        a = float(np.clip(action, -1.0, 1.0))
        reward = -abs(obs[0]) - self.lam * a * a - 1.0  # 注意：没有 -50 失败惩罚
        return obs, reward, terminated, truncated, info


bad_env = BadRewardEnv(seed=0)
w_bad, _ = cem_train(bad_env, train_psi0)
print("坏奖励下学到的 w =", np.round(w_bad, 3))
print("坏奖励下训练总回报:", round(evaluate(bad_env, w_bad, train_psi0), 1))
print("同一规则下诚实保向策略的总回报:",
      round(evaluate(bad_env, w_learned, train_psi0), 1))

obs = bad_env.reset(psi0=np.radians(30))
steps = 0
while True:
    obs, _, terminated, truncated, _ = bad_env.step(linear_policy(w_bad, obs))
    steps += 1
    if terminated or truncated:
        break
print("初始误差 30° 时", steps, "步就结束了，terminated =", terminated)
```

预期输出：

```text
坏奖励下学到的 w = [ 2.396  1.338 -0.431]
坏奖励下训练总回报: -30.8
同一规则下诚实保向策略的总回报: -207.2
初始误差 30° 时 16 步就结束了，terminated = True
```

发生了什么：学到的 `w0` 变成了**正**的——误差越大越往同方向打，16 步就把船头甩出 90° 主动结束回合。这不是算法笨：在这套计分规则下，认真保向 200 步要扣约 207 分，而"自杀"只扣约 31 分，自杀确实是更优解。把这策略按 10.4 的冻结规则评估，成功率是 0/5。**智能体优化的永远是你写下的奖励，而不是你心里的意图**——这就是 §6.5.3 强调终止/截断/奖励语义不能混用的原因：奖励和结束条件是一体的，改任何一个都要重新检查"最优行为"变成了什么。

## 10.6 工业化算法：stable-baselines3 的 PPO 骨架

CEM 适合几个参数的小策略；真实项目动作是四维、观测十几个字段、还要神经网络策略，主流选择是 PPO（Proximal Policy Optimization，近端策略优化——每次更新幅度受约束、训练稳定的策略梯度算法）。stable-baselines3 是 PyTorch 生态里成熟的 RL 库，安装命令：

```bash
pip install stable-baselines3
```

最小用法骨架如下。**注意：本机验证环境未安装 stable-baselines3，以下代码未实际运行验证，仅作结构示范**（它也是第 11 章与后续项目工作的起点）：

```python
import gymnasium as gym
from gymnasium import spaces
from stable_baselines3 import PPO

class GymHeadingEnv(gym.Env):
    """把我们的 HeadingEnv 包装成 gymnasium 标准接口。"""

    def __init__(self):
        super().__init__()
        self.inner = HeadingEnv(seed=0)
        self.observation_space = spaces.Box(-np.pi, np.pi, shape=(2,),
                                            dtype=np.float32)
        self.action_space = spaces.Box(-1.0, 1.0, shape=(1,), dtype=np.float32)

    def reset(self, *, seed=None, options=None):
        return self.inner.reset().astype(np.float32), {}

    def step(self, action):
        obs, reward, terminated, truncated, info = self.inner.step(float(action[0]))
        return obs.astype(np.float32), reward, terminated, truncated, info


env = GymHeadingEnv()
model = PPO("MlpPolicy", env, seed=0, verbose=1)  # MlpPolicy = 多层感知机策略
model.learn(total_timesteps=100_000)
model.save("ppo_heading.zip")

# 用学好的策略跑一回合
obs, _ = env.reset()
done = False
while not done:
    action, _ = model.predict(obs, deterministic=True)
    obs, reward, terminated, truncated, _ = env.step(action)
    done = terminated or truncated
```

对照关系：`model.learn()` 替代了我们的 `cem_train`，`model.predict()` 替代了 `linear_policy`，环境契约（五元组、限幅、种子）原样保留。真实项目接入时，§4.5.1 还有一条专门针对 PPO 的纪律：概率比计算必须用**采样动作**及其分布，环境内部 clip 过的动作不能拿去和原分布混算；§4.5.5 则提醒百万级训练步数对环境和网络的推理速度有硬约束，需要提前实测吞吐。这些等骨架跑通之后再逐条落实。

## 10.7 常见错误

**错误 1：角度不包络，±180° 处奖励跳变。** 目标 0°、当前 179°，下一步转到 -179°，误差数值从 3.12 跳到 -3.12，看着像误差 6.24 rad，策略学到"躲开这个方向"。

```python
err = self.psi - self.psi_ref            # 错：跨 ±pi 时跳变
err = wrap_angle(self.psi - self.psi_ref)  # 对：包络到 (-pi, pi]
```

**错误 2：用评估场景调参，或看到失败就换场景。** "这个初始艏向总失败，删掉再算成功率"等于裁判改规则。正确做法：评估集写入代码顶部就不再动，失败如实报告、进下一轮开发，另备开发场景用于日常调试（对应 §6.5.4：看过失败并用于改进的数据，下一轮只能标为开发证据）。

**错误 3：把 `truncated` 当 `terminated` 处理。** 时间上限只是"计时器响了"，把它当失败扣 -50，会惩罚那些"慢但稳"的策略；反过来把失败当截断不给惩罚，就会养出 10.5 节的自杀策略。两个标志分开判断、分开记录结束原因。

**错误 4：动作不限幅，或限幅了却不留痕。** 策略输出 3.7 直接送进动力学，力矩凭空放大 3.7 倍，仿真理所当然"学得好"——那是物理上做不到的力矩。正确写法：`a = np.clip(action, -1, 1)` 并在 `info` 里记录是否发生了裁剪（§4.5.1：不允许静默限幅，训练统计中必须可见）。

## 10.8 动手练习

**练习 1（奖励权衡）**：把 `lam` 分别改成 0.0 和 1.0 重新训练，在冻结评估集上比较成功率和动作幅度（可在回合里累计 `a*a` 的平均作为能耗指标）。描述三组结果体现的精度—能耗权衡。

**练习 2（换目标）**：把 `env.psi_ref` 改为 `np.radians(45)` 重新训练并评估。注意观测里的误差已经是相对 `psi_ref` 的，环境动力学不用动。想一想：为什么换目标不需要重写奖励函数？

**练习 3（多种子纪律）**：用 `seed=1, 2, 3` 各跑一次 `cem_train`，比较三次学到的 `w` 和冻结评估成功率。如果某个种子成功率不到 5/5，按 §6.5.2 的精神，报告里应该怎么写？

### 参考答案

**练习 1**：`lam=0.0` 时控制惩罚消失，`w` 的绝对值通常变大、动作更激进，误差收敛略快但能耗指标显著变差，还可能出现贴近 ±1 的"梆-梆"式动作；`lam=1.0` 时策略变得保守，动作幅度小、能耗低，但收敛慢、末段误差可能蹭不到 2° 容差内导致成功率下降。`lam=0.1` 是两者之间的折中。要点：**改惩罚权重就是在精度与能耗之间移动最优点，没有免费的午餐**。

**练习 2**：只需 `env.psi_ref = np.radians(45)` 后重新训练（`BadRewardEnv` 实验同理）。因为观测 `_obs()` 和奖励都建立在 `psi - psi_ref` 的相对误差上，目标角只是一个零点平移——这正说明"把任务误差表示在合适坐标系里"（§6.3.2 的观测设计思想）能让策略与目标解耦。

**练习 3**：不同种子的采样序列不同，学到的 `w` 会有差异（例如 `w0` 在 -2.3~-3.0 间波动），多数种子仍能 5/5，但不保证。若某种子失败，正确写法是如实报告"3 个种子成功率分别为 5/5、4/5、5/5，失败场景为初始艏向 XX°"，绝不能把表现差的种子悄悄重跑或剔除——§6.5.2 要求种子间散布单独报告、不挑选有利种子。
